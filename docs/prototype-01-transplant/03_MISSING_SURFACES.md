# Prototype 01 missing surfaces

This register distinguishes visual concepts present in the canonical source from product capabilities backed by the current application. No missing backend is invented.

| Prototype concept                      | Current functional status               | Canonical treatment                                                                                     | Backend change |
| -------------------------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------- | -------------- |
| Persistent community feed and comments | No matching persistent product contract | Keep the original composition with an honest empty or future state and links to real community surfaces | None           |
| Espaços persistentes                   | Not available                           | Retain the original tab and show `Em breve` in the same component system                                | None           |
| Physical events                        | Not available                           | Retain hierarchy without publishing fictional events                                                    | None           |
| Cinema                                 | No real route                           | Keep the hub item non-interactive and explicitly future-facing                                          | None           |
| Demo counters and sample activity      | Not real data                           | Replace with real counts when available; otherwise use canonical empty states                           | None           |
| Prototype-only profile modules         | No matching data contract               | Preserve module position with an honest empty state                                                     | None           |

## Extension rule

Functional routes absent from the source must be composed from copied Prototype 01 fields, rows, cards, sheets, dialogs, empty states, page frames, and responsive rules. V1, Phase 01, and Visual Zero presentation components are not valid fallbacks.
